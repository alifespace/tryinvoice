# M1.4-db-migration-and-rls：数据库迁移与多租户 RLS 独立验收

- **目标**：以已验收的 `M1.1-S1` 后端骨架为基线，独立完成 PostgreSQL/Supabase 数据库 Schema、幂等迁移运行器与多租户 RLS 隔离，并关闭原 `M1.1` 尚未验收的数据库范围。
- **前置依赖**：`M1.1-S1` 已由 Critic/Finalizer 验收，且 `ralph-code-stats` 中存在对应代码量基线。
- **范围与约束**：
  - 保留原 `docs/tasks/M1.1-backend-scaffold-and-db.md` 及其执行证据，不改写原 Task；本 Task 仅承接未验收的数据库迁移与 RLS 范围。
  - 创建 `user_profiles`、`rule_templates`、`reimbursement_batches`、`raw_documents`、`transactions`、`transaction_documents`、`jobs` 7 张表以及 `docs/lld.md` 规定的索引，列名、类型、默认值、外键与空值约束不得擅自变更。
  - 所有业务表启用 RLS：普通用户只能访问自己的 `user_id` 数据；`rule_templates.user_id IS NULL` 的系统默认模板允许读取但不允许普通用户写入。
  - 提供按文件名排序执行的迁移运行器和 `schema_migrations` 记录；每个迁移文件使用独立事务，后一文件失败不得回滚此前已经成功并登记的迁移。
  - 复用当前工作区中尚未验收的迁移实现作为候选实现，由 Builder 按本 Task Spec 检查和修正；不得把既有实现直接视为已验收，也不得修改 `M1.1-S1` 已验收范围。
  - 本 Task 的代码量以已记录的 `M1.1-S1` 快照为基线独立核算；只保留核心迁移/RLS 集成测试，满足 `Test:Feat <= 1.3` 或新增测试 `< 450` 行之一。
  - 测试使用临时 PostgreSQL 或明确隔离的 Supabase 测试环境；严禁写入生产数据，严禁把数据库密码、JWT 或 Supabase Secret 写入仓库、日志、事件和报告。
- **验收标准**：
  - 迁移首次执行返回本次应用文件，重复执行无新增；同一 SQL 文件直接重放不报错。
  - 使用真实 PostgreSQL 引擎证明：后一迁移失败时，之前成功的迁移及 `schema_migrations` 记录仍然存在。
  - 7 张业务表、列、索引和 RLS 开启状态与 `docs/lld.md` 一致；以非超级用户角色验证用户 A/B 互不可见、不可越权写入。
  - 系统默认规则模板对普通用户可读但不可修改；用户自有模板只对所有者可见和可写。
  - tests、lint、typecheck、audit、coverage、complexity、duplication 7 项门禁全部通过，覆盖率不低于 90%，最大圈复杂度不高于 10。
  - Finalizer 将验收证据、实际代码量与 `M1.4` 基线写入 `ralph-metrics` 和 `.ralph/agent/task-progress.json`，不得沿用未验收的 `M1.1-S2` 结论冒充通过。
