# M2.5-transaction-review-api：交易查询、人工修订与契约收口

- **目标**：提供批次处理结果的查询与人工复核写回能力，完成 M2 的后端 API 闭环。
- **前置依赖**：`M2.4-batch-processing-pipeline`。
- **范围与约束**：
  - 实现 `GET /batches/{id}/transactions`，返回按 `category → region_scope → region_detail` 组织的交易、关联凭证、支付状态、规则标记以及批次缺漏告警。
  - 实现 `PATCH /transactions/{tx_id}`，支持 `docs/lld.md` 已约定的分类、均分人数、小费、配对关系与备注人工修订；成功写回后设置 `is_user_verified=true`。
  - 所有查询和修订必须经过鉴权及 `user_id` 租户隔离；不存在或不属于当前用户的资源不得泄露其存在性或内容。
  - 人工修订结果必须与 M2.4 的保护语义衔接：后续再次执行批处理时，已确认字段不得被自动计算覆盖。
  - 更新并确定性校验 `contracts/openapi.json`；只增加关键 API/集成测试，不重复 M2.2/M2.3 已覆盖的纯逻辑规则测试。
  - 本 Task 专业预估约 1,000 行，但估算不得被当作硬门禁；总改动量硬上限为 2,000 行。Planner 应根据实测模块复杂度分配 Subtask 预算并保留合理返工余量，禁止从预估值中重复扣减“返工余量”。
  - 不包含 Excel/ZIP 导出、后台队列、iOS UI、数据库迁移、真实云端调用或新增规则能力。
- **验收标准**：
  - 未认证请求返回 `401`；跨租户批次和交易不可查询或修改。
  - 查询结果的三级分组、金额、凭证关联、支付状态、规则标记和缺漏告警与数据库事实一致，排序稳定。
  - 合法人工修订可持久化并标记 `is_user_verified=true`；非法字段或不合法值返回明确的 `4xx`，且不产生部分写入。
  - 修订后再次运行 M2.4 处理，人工确认字段与关联关系按设计保留。
  - `contracts/openapi.json` 与应用路由一致；7 项门禁全部真实通过。
  - 本 Task 按独立基线核算，总改动量不超过 2,000 行；测试满足 `Test:Feat <= 1.3` 或新增测试低于 450 行之一。
