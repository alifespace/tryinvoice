# M4.1-test-backend-environment：低成本测试后端与远端冒烟环境

- **目标**：基于现有 `backend/Dockerfile` 在 Render Free 建立非生产测试后端，接入既有 Supabase 测试数据库和对象存储，为 iOS 联调提供稳定的 HTTPS 基地址。
- **前置依赖**：`M3.2-backend-e2e-and-deployment-config`。
- **范围与约束**：
  - 添加 Render 声明式部署配置、脱敏环境变量清单和确定性冒烟脚本；后端仍使用现有 Dockerfile，不引入第二套启动方式。
  - 免费实例允许休眠与冷启动，仅用于开发测试，不承诺生产可用性；不得依赖本地持久磁盘。
  - 真实 Render 服务创建、GitHub 授权、Secrets 注入与首次部署属于外部写入：必须先在进度账本登记 attempt ID、完整参数和清理方式，再取得项目所有者授权。
  - 只连接现有 Supabase 测试环境和测试对象存储；严禁生产数据、真实票据、真实 API Key 或完整 OCR 文本进入仓库、CI Artifact 或日志。
  - 测试环境状态以 `docs/environments/test-environment.md` 为准：保留旧表、旧 Auth 用户和旧 bucket，TryInvoice 使用独立表、专用测试用户、私有 bucket 与对象路径前缀。
  - Render/Supabase/R2 凭证只能通过平台 Secrets 注入；公开仓库不得包含任何真实值。
  - 预估总改动量约 600 行（功能与配置 350 行、测试 250 行），不超过 2,000 行；新增测试控制在 250 行以内。
- **验收标准**：
  - 部署声明静态校验通过，容器启动命令与 `GET /api/v1/health` 健康检查一致。
  - 经授权完成真实部署后，HTTPS 健康检查返回成功，未认证访问受保护接口返回 401。
  - 使用仅存于 Secrets 的测试账号完成最小鉴权与合成数据 API 冒烟；远端日志经过凭证和业务原文扫描。
  - 记录服务 URL、部署回执、失败诊断与删除/停用方式，但不得记录 Secret。
