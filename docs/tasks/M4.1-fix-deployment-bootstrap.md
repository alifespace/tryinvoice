# M4.1-fix-deployment-bootstrap：测试容器确定性启动与自动初始化

- **目标**：修复 Render Docker Command 不解释 `&&`、导致迁移完成后进程直接退出的问题，建立可复现、幂等且无需人工切换命令的容器启动路径。
- **前置依赖**：`M4.1-test-backend-environment` 已形成部署候选；真实测试环境已确认迁移 `0001_init_schema.sql` 与 CMI 默认模板 seed 可分别成功执行。
- **范围与约束**：
  - 使用单一标准容器入口依次执行数据库迁移、默认模板 seed，并以 `exec` 语义启动 Uvicorn；优先采用小型 POSIX 入口脚本或等价的确定性启动器，不新增框架或第二套部署体系。
  - 迁移与 seed 必须保持幂等；任一步失败都必须阻止 API 启动并返回非零退出码，成功后不得遗留包装进程吞掉终止信号。
  - 更新 `backend/Dockerfile`、Render 声明/环境文档及必要测试；不得把数据库密码、完整连接串或任何 Secret 写入镜像、仓库、日志和测试夹具。
  - Render Free 不提供 Pre-Deploy Command 时，容器入口是测试环境的唯一初始化路径；不得依赖人工临时修改 Docker Command。
  - 不修改认证算法、业务 API、数据库表结构或 iOS 客户端。
  - 预估改动约 330 行（功能与配置约 180 行、测试约 150 行），不超过 2,000 行；新增测试低于 450 行。
- **验收标准**：
  - 冷启动时按“迁移 → seed → Uvicorn”顺序执行；迁移或 seed 失败时 API 不启动，成功时 Uvicorn 成为常驻主进程。
  - 重复启动不会重复迁移或复制默认模板，终止信号能正确传递给 Uvicorn。
  - Docker/启动器测试、后端测试、lint、类型检查、安全审计、覆盖率、复杂度和重复代码门禁全部通过。
  - 真实 Render 复验只记录部署 ID、状态、健康检查与脱敏日志；任何凭证不得进入验收文档。
