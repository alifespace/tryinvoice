# M4.1-fix-supabase-jwks-auth：Supabase ES256/JWKS 鉴权兼容

- **目标**：让后端验证 Supabase 当前由 ECC P-256 签发的 ES256 Access Token，完成测试账号鉴权与合成数据最小 API 冒烟，同时兼容密钥轮换。
- **前置依赖**：`M4.1-fix-deployment-bootstrap`；Supabase 测试项目已启用新版 JWT Signing Keys，现有后端仅接受 `HS256` 的实现已由真实门禁确认不兼容。
- **范围与约束**：
  - 使用 PyJWT 的成熟 JWK/JWKS 能力或等价成熟组件，从 Supabase 项目的标准 JWKS 端点获取公钥并验证 ES256 Token；禁止自写密码学实现。
  - 校验签名、允许算法、`exp`、`sub`、`iss`，并按项目配置校验适用的 `aud`；拒绝 `alg=none`、算法混淆、未知 `kid`、过期 Token、错误 issuer/audience 和缺失 subject。
  - JWKS 必须有有界缓存、超时与密钥轮换刷新策略；网络或解析失败返回可恢复的 401/503 边界，不得泄露 Token、JWKS 正文或内部凭证。
  - 若保留旧 HS256 测试兼容，只能通过显式测试/迁移配置启用，禁止默认接受任意算法或把 Legacy JWT Secret 作为新版 Token 的长期方案。
  - 只修改后端认证依赖、配置、相关测试、环境变量示例与契约说明；不实现 iOS 登录 UI、公开注册、账号管理页面或生产密钥配置。
  - 预估改动约 650 行（功能约 350 行、测试约 300 行），不超过 2,000 行；新增测试低于 450 行。
- **验收标准**：
  - 单测覆盖有效 ES256、密钥轮换、未知 `kid`、过期、错误 issuer/audience、算法混淆、JWKS 超时/失败及日志脱敏。
  - 未认证请求继续返回 401；合法 Supabase 测试账号 Token 能访问受保护的最小 API，跨租户数据仍不可见。
  - 经项目所有者授权后，使用仅存于平台 Secret 的测试账号完成真实鉴权与合成数据最小 API 冒烟；仓库、日志和 Artifact 不含 Token、密码或业务原文。
  - 七项门禁全部通过，最大圈复杂度不超过 10。
