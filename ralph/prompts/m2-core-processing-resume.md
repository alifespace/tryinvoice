Planner 将旧 Builder 的预算与复杂度阻塞记为本阻塞项第1次重规划证据，然后直接为 `M2.5-S2` 编写新 Spec 并发布 `spec.ready`：

## 后续事件与完成条件

- Builder 能在 Spec 内解决时继续实现并跑完七项门禁；全部通过后才发布 `build.done`。
- Builder 自身发现新 Spec 仍存在无法同时满足的边界、前置条件、白名单、代码量或复杂度冲突时，必须携带实测证据发布 `task.replan`，禁止发布 `loop.cancel`。
- Planner 收到 `task.replan` 后继续修订或重拆；只有本阻塞项在 Planner 侧累计4次重规划仍未通过，且M2没有其他可执行事项时，才允许 `loop.cancel`。
- Critic 独立复核通过、Finalizer 确定性收尾并将 `M2.5` 标为 accepted 后，Planner确认 M2.1-M2.5 全部完成，才发布 `LOOP_COMPLETE`。
